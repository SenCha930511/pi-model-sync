# Repository Guidelines

## Project Overview

pi-model-sync is a **dual-host coding-agent extension (omp / upstream pi)** that routes the model used by newly spawned subagents (task / eval `agent()` / workpool workers) and by supported subagent plugin tool calls (`@mjakl/pi-subagent`, `pi-subagents`, `@tintinweb/pi-subagents`, `@gotgenes/pi-subagents`, `pi-interactive-subagents`, `edxeth/pi-subagents`), based on the *spawning session's current model*, via a two-layer JSON config holding named presets (one active preset per layer). It also exposes a `/model-sync` slash command to manage profiles, presets, and per-session routing. Not a CLI, not a library. Loaded and executed by the host. MIT license, v0.6.0, published to npm as `@sencha930511/pi-model-sync`.

Key behaviors: running subagents never switch models mid-flight; nested spawns are intercepted using the spawning session's own model; selectors that fail to resolve fall through to default routing with a one-time per-session TUI warning; an explicit per-call `model` in a pi-subagent call is never overwritten (frontmatter-level defaults are overridden by injection on purpose); an explicit omp per-call model is left alone. Config documents are either legacy `{ profiles }` or named `{ activePreset?, presets }`; only the active preset's ordered profile list routes; a missing, empty, or dangling active preset fails closed, with the reason surfaced by `/model-sync list|show`. `add`/`set`/`remove`/`move` edit only the active preset; the first successful `preset create`/`preset copy` converts a legacy document to `presets.default`, and `preset rename default <name>` converts it to `<name>`; every write path deep-clones the whole document. Session overrides (`use-session`), pause/resume, the route log, and warning dedupe are in memory and never written to disk.

## Architecture & Data Flow

Eight modules: `adapters.ts` (pure detection and dialect translation), `config.ts` (config I/O and the domain model), `resolver.ts` (host model/selector resolution), `session.ts` (per-session mutable state), `hooks.ts` (spawn and `tool_call` interception), `completions.ts` (argument completion), `commands.ts` (dispatch, writes, display), `index.ts` (registration only). Runtime import edges: `index.ts → commands, completions, hooks, session`; `commands.ts → adapters (type-only), config, resolver, session`; `completions.ts → config, session (type-only)`; `hooks.ts → adapters, config, resolver, session`; `session.ts → resolver, adapters (type-only), config (type-only)`; `resolver.ts → adapters`; `config.ts` imports only Node builtins; `adapters.ts` imports nothing.

- **Entry**: `index.ts` default-exports `modelSync(pi: ExtensionAPI)`. The host loads it via `package.json` → `omp.extensions` / `pi.extensions: ["./index.ts"]`. `modelSync` creates a `SessionState`, sets the label when supported, registers the omp-only `before_subagent_spawn` hook (wrapped in try/catch because upstream pi lacks the event), registers `tool_call`, registers `session_start` and `model_select` cache refreshes in try/catch (omp has no `model_select`), and registers the `model-sync` command. The handlers, completion, and command dispatch live in their modules; the factory closure owns the only mutable per-session state.
- **Session state** (`session.ts`): `warnedSelectors`, `warnedAdapterConflicts`, a 50-entry `routeLog`, an optional in-memory `presetOverride`, `paused`, the cached `cwd`, the authenticated model ids for completion, and `statusVisible`. Warning dedupe is per session, not module-global. `sessionSelection(state)` turns the override/pause into the `SessionSelection` passed to `readConfig`/`projectActiveProfiles`.

**Spawn flow (hot path).** `hooks.handleBeforeSubagentSpawn`:

1. `currentModelRef(ctx)` → `{ provider, id }`; an unrecognizable model returns `undefined` before any config read.
2. If the session is paused, record `skipped: session paused` and return `undefined`.
3. If the event has `invocationKind`, no `modelRole`, and a non-empty pattern list with no entry matching the current model, treat it as an explicit omp per-call model and leave it alone (decision 11). Older hosts without `invocationKind` stay routable.
4. `readConfig(ctx.cwd, sessionSelection(state))` never throws. It resolves the active layer, reads it, and returns the active-preset or session-preset projection. A missing file is not an error. Any file/parse error or dangling selection yields zero profiles plus a warning (the spawn hook ignores the warning, so fail-closed routing is silent on this path).
5. `findProfile(config, modelRef)`: case-insensitive; `main` without `*` must equal `provider/id` or bare `id`; `*` is an explicit glob (crosses `/`, all other regex metachars escaped); first match in profile order wins; no substring matching.
6. `pickSubagentSelector(profile, agentName)`: string form returns itself; object form tries the exact agent key, then an optional case-insensitive pass when `profile.agentMatch === "case-insensitive"`, then the `"*"` default.
7. `selectorResolvable(ctx, selector)`: omp uses `ctx.models.resolve()`; upstream uses `modelRegistry`. An unresolvable selector warns once per session and falls back to default routing.
8. On success returns `model: [selector, ...originalPatterns]` (originals stay as retry fallbacks) plus routing note `pi-model-sync: <agent> → <model> (main: <main>)`. The decision is appended to the session route log.
9. **Invariant: this path must never throw.** Any failure returns `undefined` (no interception, default routing).

**Subagent plugin flow (`tool_call` hook).** `hooks.handleToolCall`:

1. Tool gate. `toolName` must be one of the adapter tool names (`subagent`, `Agent`). Everything else passes through untouched.
2. Adapter detection lives in `adapters.ts`. Candidates are filtered by the schemas from `pi.getAllTools()` first. Each adapter declares required and forbidden property names, and every adapter requires a `model` property in the schema fingerprint. `collectSchemaProps` recurses through `properties`, `items`, `anyOf`, `oneOf`, `allOf`, local `$ref` targets, and `$defs`/`definitions`. Without `getAllTools()`, or when no schema matches, a stricter call-shape check (`fallbackProps`) selects the adapter. Zero matches → no interception; more than one → skip with a one-time per-session TUI warning.
3. `collect(input)` returns only injectable slots. An explicit model (`model`, nicobailon `options.model`, per-item models, child models), a resume, or a management action yields no slot, so the config is never read for those calls.
4. For each slot, `pickSubagentSelector` picks the selector (exact → optional case-insensitive → `*`). `normalizeSelector(selector, dialect)` translates `:level` per plugin (`suffix` keeps it in the model, `field` splits it into `thinking`, `none` strips it) and rejects `@alias`, glob, or bare ids the plugin cannot resolve.
5. `selectorKind` distinguishes `provider-id`, `bare`, and `unknown` using omp's `ctx.models.list()` or the upstream registry. This keeps a slash-containing bare id such as `meta-llama/Llama-3` classified as bare, so an exact-only plugin rejects it instead of mistaking it for `provider/id`. `bareSelectorUnique` counts providers by the full id.
6. `selectorResolvable(...)` validates the base selector (memoized per event). Unresolvable → skip with a one-time warning.
7. `applyModelSpec` writes `model` and, only when empty, the thinking field. The handler mutates `event.input` in place and returns `undefined`; upstream pi documents in-place mutation, omp passes the same object for non-edit tools, and returning `{ input }` would overwrite another extension's last-wins input.
8. Every routed or skipped slot is appended to the session route log. Same never-throw invariant.

**Command flow.** `commands.commandHandler` parses quotes, rejects unknown `--` options, accepts `--help`/`-h` anywhere, extracts `--project`, and dispatches `/model-sync list|show|add|set|remove|move`, `/model-sync preset list|create|copy|rename|use|remove`, `/model-sync status [off]`, `/model-sync use-session <preset|off>`, `/model-sync pause|resume`, `/model-sync log [clear]`, `/model-sync doctor`, `/model-sync init`, and `help`. Writes default to the **global** file; `--project` targets `getProjectConfigPath(cwd)` (`.omp`, falling back to `.pi` by existence). `preset list` always reports the active layer, so `--project` only affects writes. A missing target file is not an error; `loadForWrite` starts from the legacy empty document. It refuses a corrupt or structurally invalid existing file, surfaces parse warnings (including unknown keys), and returns `cloneConfig(...)` (full-document deep clone). `loadActiveForWrite` refuses `add`/`set`/`remove`/`move` when no preset is active or the active name dangles, printing the projection warning, available preset names, and `No changes were written (target: …)`. While a session override or pause is active, writes still target the on-disk active preset and say so. `saveConfig` writes atomically and updates a visible status bar. Preset commands operate on the raw document (they do not require an active preset). `cmdPresetRename` rebuilds the preset map to preserve order and updates `activePreset` when the old name was active. `cmdMove` reorders the active preset and refuses edge moves. `preset use` without a name opens `ctx.ui.select()` when the host has a UI.

**Session commands.** `use-session <name>` validates the name against the target layer's presets and sets `state.presetOverride`; `use-session off` clears it. `pause`/`resume` toggle `state.paused` and keep any override. `status [off]` reports the layer, on-disk preset, session preset, current model, matched profile, cached model count, and route-log count; it sets or clears `ctx.ui.setStatus("pi-model-sync", …)`. `log [clear]` prints or clears the last 50 decisions. `doctor` scans the active and inactive layers, every preset/profile, and reports unknown keys, shadowed literal rules, selectors the host or installed plugins cannot resolve, and agent keys that differ only by case. `init` creates a starter named preset from the current model and refuses an existing file.

**Command completion.** `completions.modelSyncArgumentCompletions(prefix, state)` suggests the top-level subcommands, `preset` actions, profile `main` values and agent keys for `add`/`set`/`remove`/`move`, existing preset names for `preset use`/`remove`/`copy`/`rename`, session actions, and authenticated model ids for `show`, `add`, and the model position of `set`. It reads the global target by default and the project target when `--project` is present. A typed `--project` flag is preserved in the completed value and is not suggested twice. It must never throw and returns `null` on unknown or malformed input. It uses `state.cwd` (cached by `session_start`/commands) with `process.cwd()` as the fallback, because the host's completion signature does not include `ctx`.

**Config resolution precedence** (`config.ts`):

- Global path: env `PI_MODEL_SYNC_CONFIG` (highest; relative paths resolve against the session cwd via `getGlobalConfigPath(cwd)`; a leading `~/` expands to the home directory) → `PI_CODING_AGENT_DIR/pi-model-sync.json` (also expands `~/`) → `~/.omp/agent/pi-model-sync.json`; **dual-host fallback**: when the `~/.omp` file does not exist and `~/.pi/agent/pi-model-sync.json` does, the `.pi` path wins (write target stays `~/.omp` when neither exists).
- Project path: `<cwd>/.omp/pi-model-sync.json` (cwd only, no upward search); same isomorphic fallback to `<cwd>/.pi/pi-model-sync.json` by file existence.
- An existing project file **wholly replaces** the global file (even broken JSON counts as "exists"). No per-key merge. Each layer is a complete document with its own `presets` and `activePreset`, so preset selection is per layer and the global preset does not affect routing while a project file exists.

**Preset document model** (`config.ts`):

- Parse boundary `parseConfig` returns `{ config, error, warnings }` and never throws. A structurally invalid document (a non-object JSON root, mixing `profiles` with `presets`/`activePreset`, `activePreset` without `presets`, a non-array `profiles` value, non-object `presets`, a preset value that is not an array, a blank/whitespace/duplicate preset name, a non-string/non-null `activePreset` value, or a non-empty root object with neither `profiles` nor `presets`) returns the shared fail-closed `INVALID_CONFIG` (`{ presets: {} }`, null prototype) with a message. `readLayer` prefixes `Invalid config file (<path>): …`; a JSON syntax error yields `Could not parse config file (<path>): …`.
- An empty string or null `activePreset` is treated as unselected, not a structural error, so `preset use` can repair it.
- `normalizeProfiles` skips invalid entries and returns warnings (`Skipped profile …`). It also parses `agentMatch` (`"exact"` or `"case-insensitive"`) and warns on unknown profile keys. `list`, `show`, and `preset list` display them; `loadForWrite` warns before a rewrite drops them.
- `projectActiveProfiles(config, selection?)` is the **only** active-selection policy. Legacy → virtual `default` with its profiles; named without `activePreset` → `{ profiles: [], warning: "No active preset is selected; no profiles are active." }`; named with a dangling name → `{ profiles: [], warning: 'Active preset "<name>" does not exist; no profiles are active.' }`. A `SessionSelection` replaces that with the named session preset or a paused/empty projection. Never falls back to another preset or to legacy.
- Preset names are single tokens (no whitespace), matched exactly and case-sensitively. A legacy document exposes the virtual `default`; `toPresetConfig` moves its profiles into `presets.default` with `activePreset: "default"`.

**Caching & writes**: reads cached by **mtime + ctime + size + inode** in module-level `layerCache`; the cache stores the raw parsed document plus warnings, not a projection, and consumers clone before editing. Cache hits refresh the map insertion order (LRU), and at 64 entries a new path evicts the oldest entry. `EMPTY_CONFIG` is the legacy `{ profiles: [] }` shared by missing files; `INVALID_CONFIG` is the shared fail-closed named document for parse/structural errors. `statFile` uses `statSync(path, { throwIfNoEntry: false })` so a missing file does not throw ENOENT. Glob patterns compile once in module-level `globCache`. Writes are atomic (`mkdir -p` → unique `<path>.<pid>.<uuid>.tmp` → `renameSync`, tmp unlinked on failure), follow a symlink to its real target so dotfile managers keep their link, pass through `parseConfig`, refuse a structurally invalid document, preserve profile order, and invalidate the cache entry for both the link and the target.

## Development Commands

`package.json` keeps **zero `dependencies` and zero root `devDependencies`**; there is intentionally no root `package-lock.json` or root `node_modules`. Install the isolated CI tools once with `npm ci --prefix .github/omp-tools`, then run `npm run check` (or `npm run check:portable` on Windows). The package ships `index.ts`, `config.ts`, `adapters.ts`, `resolver.ts`, `session.ts`, `hooks.ts`, `completions.ts`, `commands.ts`, and `llms.txt` via the `files` whitelist; npm adds `package.json`, `README.md`, and `LICENSE`.

- `npm run release:bump <X.Y.Z>`

## Code Conventions & Common Patterns

- **Language of prose**: comments, JSDoc, README.md, and all user-facing strings (`notify`, command help/output, and config errors) are **English**. Comments reference numbered design decisions; the decision legend lives at the top of `index.ts`. Use the existing box-drawing section dividers.
- **Modules**: ESM; internal imports extensionless (`from "./config"`); Node builtins with `node:` prefix; the only external import is `import type { ExtensionAPI } from "@earendil-works/pi-coding-agent"` (type-only, erased at runtime so either host loads it; declared as a `peerDependencies` wildcard per the Pi packaging convention, never bundled).
- **Naming**: camelCase functions/vars; PascalCase types; `cmd*` prefix for command sub-handlers; SCREAMING_CASE only for constants like `USAGE`; verb-first helper names (`extractAgentName`, `resolveActiveLayer`).
- **Host-facing types**: do NOT import host runtime types beyond `ExtensionAPI`. The duck-typed interfaces (`ModelsFacade`, `ModelRegistryFacade`, `UiFacade`, `ExtensionContextLike`, `SubagentSpawnEvent`, `ToolCallEventLike`, `RegistrySnapshot`, `ToolHost`) live in `resolver.ts`; narrow `unknown` payloads with `typeof`/`in`/`Array.isArray` guards. Never use `any`.
- **State**: per-session mutable state lives in the `SessionState` created by the `modelSync(pi)` factory and is passed explicitly to `hooks`, `commands`, `completions`, and `session` helpers. Do not add module-level warning sets or session overrides. The file cache and glob cache are content-addressed and safe to share across sessions.
- **Error handling**: the spawn and `tool_call` paths catch and return `undefined`. The command handler catches errors and reports `err.message` through `notify`. `writeConfig` may throw on I/O failure or a structurally invalid document; the command handler surfaces it. No `console.*` or `process.exit`. `notify(ctx, message, level)` uses `info`, `warning`, or `error`.
- **Types**: explicit return types everywhere; `unknown` + guards; no enums, generics, or decorators; standard TS only. `scripts/typecheck.mjs` checks the shipped modules via `scripts/tsconfig.typecheck.json` and `scripts/host-stub.d.ts` under `strict`, `noUncheckedIndexedAccess`, `exactOptionalPropertyTypes`, `noUnusedLocals`, `noUnusedParameters`, `noImplicitReturns`, `noImplicitOverride`, and `noFallthroughCasesInSwitch`, then checks the tests via `scripts/tsconfig.tests.json`, then compiles `scripts/host-contract.ts` against the installed `@oh-my-pi/pi-coding-agent` and `@earendil-works/pi-coding-agent` type packages via `scripts/tsconfig.hosts.json`.
- **Async**: only the command handler and interactive `preset use` are async; all config I/O is synchronous `node:fs`; no top-level await.
- **Mutation safety**: `loadForWrite` deep-clones the entire document (`cloneConfig` → `cloneProfiles` + null-prototype `cloneSubagentMap`), so editing one preset can never mutate cached sibling presets; `cmdSet`/`cmdRemove` clone the subagents map before editing; `cmdPresetCopy` clones the source list (`cloneProfiles`); `toPresetConfig` clones legacy profiles; `cmdPresetRename` moves lists within the cloned document. Cache reads return shared nested maps, so clone before editing.
- **Command semantics to preserve**: profile lookup by `main` is case-insensitive; `set <main> * <model>` updates the profile default while preserving per-agent entries (collapsing to a plain string only when no per-agent entry exists); removing entries until only `*` remains collapses back to the plain string; removing the last agent key deletes the whole profile; subcommands reject extra arguments and unknown `--` options with a usage hint; `pickSubagentSelector` semantics (exact key → optional case-insensitive pass → `*` fallback) must stay consistent with command-side edits; `add`/`set`/`remove`/`move` mutate only the active preset and `loadActiveForWrite` refuses when none is active; preset names must be single tokens; `preset create` creates an empty inactive preset and never switches; `preset copy` deep-copies without switching and refuses an existing target name; `preset rename` preserves order and updates the active name; `preset use` is a no-op when the name is already active; `preset remove` refuses the active preset; the first successful create/copy/rename on a legacy document converts it; `move` refuses edge moves.
- **Session semantics**: `use-session` and `pause` never write; `resume` keeps an override; `status off` clears the status bar; `log` keeps the last 50 entries; `doctor` reports issues with the `warning` level; `init` refuses an existing file.
- **Reader-load rules**: `modelSync` is registration only; handlers, completion, and the layer view are module scope but receive `SessionState` explicitly. Prefer `loadActiveLayerView`/`appendLayerSummary` over re-reading and re-projecting a layer in each command. Avoid one-caller wrapper helpers; inline tiny formatting.

## Runtime/Tooling Preferences

- **Runtime: Bun**: the omp host runs on Bun and executes the TypeScript sources directly; no build step, by design.
- **Zero runtime/root dependencies**: `config.ts`, `resolver.ts`, `session.ts`, `hooks.ts`, `completions.ts`, `commands.ts`, and `index.ts` use Node builtins only; there is no root `package-lock.json` and no root `node_modules`. Isolated CI tools (`typescript`, `@types/node`, `@types/bun`, `@oh-my-pi/pi-coding-agent`, `@earendil-works/pi-coding-agent`) live only in `.github/omp-tools/`. Adding a runtime dependency is a design change, not a routine edit.
- Code uses **Node-compatible APIs only** (no `Bun.file`, Bun shell, or `import.meta`); keep new code on `node:` builtins so it stays host-portable.
- `@earendil-works/pi-coding-agent` is an ambient host-supplied module on both hosts (omp forks the same `ExtensionAPI` surface); `scripts/host-stub.d.ts` provides its type-only contract for `npm run typecheck`, and `scripts/host-contract.ts` checks the real installed packages.

Manual TUI verification under a real host (`omp` and/or upstream `pi`, pointing `PI_MODEL_SYNC_CONFIG` at a throwaway file) should still cover interactive UX when changing user-facing behavior:

1. Load the extension with `omp --extension <repo path>` (and/or upstream pi), pointing `PI_MODEL_SYNC_CONFIG` at a throwaway file, never a real user config.
2. Exercise `/model-sync add|set|list|show|remove|move` on a legacy file (with and without `--project`), then `preset list|create|copy|rename|use|remove`; confirm the first create/copy converts the file to `presets.default` with `activePreset: "default"`, that create/copy/rename leave the active profiles unchanged, that removing the active preset is refused, and that copying onto an existing name is refused.
3. First-run check: point at a missing file and run `/model-sync list`, `/model-sync preset list`, and `/model-sync init`; confirm onboarding instead of an error, then confirm `init` creates a starter preset and refuses a second run.
4. Completion check: `--project` preservation, no duplicate flag, `preset copy` trailing space, add/set/remove/move suggestions, model id suggestions after a session start, and `use-session`/`status`/`log` suggestions.
5. Session check: `use-session <name>` routes without rewriting the file; `pause` stops routing; `resume` re-enables it; `status` sets the status bar; `status off` clears it; `log` shows routed and skipped decisions; `log clear` empties it.
6. Fail-closed checks: remove `activePreset` or point it at a missing name; confirm no interception, warnings in `list`/`show`, and add/set/remove/move refusal. Set `activePreset` to `""` or `null` and confirm `preset use` repairs it. Hand-edit a mixed document, a typo-only root, and a non-array `profiles`; confirm the config error and write refusal. Add an unknown root key and confirm the warning and that a rewrite drops it.
7. `show`/`doctor` checks: a selector that only one plugin dialect accepts, a glob rejected by a suffix-only plugin, a slash-containing bare id rejected by edxeth, a shadowed literal rule, and agent keys that differ only by case.
8. Perf checks: a missing-config read loop and a multi-selector upstream `tool_call` batch; confirm no ENOENT throw path and one registry listing per event.
9. Spot-check invariants from this guide: never-throwing spawn path, whole-file project-over-global replacement with independent per-layer active presets, atomic writes + symlink preservation + cache invalidation, deep-clone isolation between presets, per-session warning isolation, and, when an older build is available, that it reads a preset file as empty and rewrites it as legacy.

When changing behavior, update `README.md`, `llms.txt`, and `AGENTS.md` (English) in the same change.
